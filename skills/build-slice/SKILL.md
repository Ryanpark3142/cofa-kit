# build-slice — 한 슬라이스 구현

## 순서
1. PLAN.md 에서 이번 슬라이스의 요구 ID·검증 방법을 읽는다. `req_upsert` 로 상태 `doing`.
2. 관련 파일만 읽는다. 무엇을 어느 파일에 할지 3줄로 말한다.
3. **테스트 먼저**(가능하면): 슬라이스 검증 방법을 테스트나 실행 스크립트로 만든다. 처음에 실패하는 것을 확인한다(이 의도된 실패는 `$debug` 대상이 아니다).
4. 구현한다. 최소한으로. 요구 ID 와 무관한 정리·리팩터링은 하지 않는다.
5. 실행·테스트를 `node .cofa/kit/scripts/kit.mjs run -- <명령>` 으로 돌린다(증거 번호가 남고, 0건 실행은 통과로 치지 않는다). 결과를 그대로 보여준다. 웹이면 서버를 `0.0.0.0` 으로 띄우고 포트·경로를 알려준다(사용자가 Browser 탭에서 확인).
6. 통과하면:
   - `req_upsert` 상태 `done`(사람 확인·엣지 케이스까지 끝났으면 `verified` + evidence 에 명령과 결과)
   - 설계 선택이 있었으면 `log_decision`
   - `log_work` 한 줄
   - 커밋: `git add <바뀐 파일> && git commit -m "<type>: <무엇> (<요구 ID>)"`
7. 실패하면 `$debug`. 같은 수정을 두 번 넘게 반복하지 않는다.

## 보고
```
슬라이스 N 완료 (R2, R3)
- 변경: src/x.py 의 parse(), tests/test_x.py
- 검증: `python -m pytest -q` → 5 passed
- 미검증: 빈 파일 입력
- 다음: 슬라이스 N+1
```

## 금지
- 여러 슬라이스를 한 번에
- 테스트를 통과시키려고 테스트를 고치기(요구가 바뀐 경우만, 이유를 말하고)
- 실행하지 않고 "동작할 것입니다"
