# playbook — 과제 유형별 요령

1. 지시서의 산출물로 유형을 고른다(여러 개면 주 유형 + 보조).
2. 해당 참고 파일만 읽는다(전부 읽지 않는다).

| 유형 | 판별 단서 | 참고 |
|---|---|---|
| 웹 서비스·대시보드 | 화면, 버튼, 입력 폼, "웹앱", 미리보기 | `references/web.md` |
| 데이터 분석·리포트 | CSV/엑셀 제공, 원인 분석, 집계, 시각화, 보고서 | `references/data.md` |
| API·백엔드 | 엔드포인트, 요청/응답, 다른 시스템 연동 | `references/api.md` |
| 기존 코드 수정 | 저장소가 주어짐, 버그, 기능 추가, 리팩터링 | `references/legacy.md` |
| 자동화·배치·CLI | 반복 업무, 파일 처리, 스케줄, 규칙 판정 | `references/automation.md` |
| LLM 기능 | 요약·분류·추출·챗봇을 결과물 안에 넣기 | `references/llm-feature.md` |
| 문서 산출물 | 기획서·설계서·분석 보고서가 주 산출물 | `references/report.md` |
| 반도체·제조 용어 | 수율, 웨이퍼, 로트, 불량, 설비, SPC | `references/semiconductor.md` |

3. 참고 파일의 「최소 구조」 를 `$plan` 의 설계안 후보로, 「검증」 을 슬라이스 검증 방법으로, 「함정」 을 위험 목록으로 옮긴다.
4. 참고 파일은 일반 요령이다. 지시서·담당자 답과 다르면 지시서·담당자 답을 따른다.
