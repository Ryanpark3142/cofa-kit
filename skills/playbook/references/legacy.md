# 기존 코드 수정

## 시작
1. 실행 방법과 테스트 명령을 찾는다(README, package.json scripts, Makefile, pyproject). **기준선**: 고치기 전에 테스트를 한 번 돌려 결과를 남긴다(이미 실패하는 테스트가 있는지).
2. 1쪽 지도: 진입점 → 주요 모듈 → 데이터 흐름. 파일:함수로. 근거(읽은 것) / 추론 / 미확인을 구분.
3. 고칠 곳을 좁힌다: `grep -rn` 으로 관련 이름 검색, 호출하는 곳까지.

## 원칙
- 최소 변경. 주변 스타일·이름 규칙을 따른다. 관련 없는 리팩터링·포맷 변경 금지(diff 가 커지면 평가자도 나도 못 읽는다).
- 버그는 재현 테스트를 먼저 만들고 고친다.
- 공개 인터페이스(함수 시그니처, API 응답 형식)를 바꾸면 호출하는 곳을 모두 확인한다.

## 검증
- 기준선 대비 테스트 결과 비교(새로 깨진 것 0)
- `git diff --stat` 으로 변경 범위가 요구에 맞는지

## 함정
- 기준선 없이 고쳐서 원래 깨져 있던 것을 내 탓으로 오해
- 의존성 버전을 올려 다른 곳이 깨짐
- 생성 파일·빌드 산출물을 직접 수정
