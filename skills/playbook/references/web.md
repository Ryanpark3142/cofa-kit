# 웹 서비스·대시보드

## 최소 구조 (설치된 것 우선)
- Node 만 있으면: 정적 HTML/JS + `node:http` 서버 한 파일, 또는 Express 가 이미 있으면 Express.
- Python 이 편하면: FastAPI/Flask 가 설치돼 있을 때만. 없으면 `http.server` + 정적 파일.
- 프론트 프레임워크(React 등)는 요구가 복잡한 상호작용을 요구할 때만. 빌드 시간·의존성 설치 시간을 계산에 넣는다.
- 저장이 필요하면 JSON 파일 또는 SQLite. 별도 DB 서버는 요구에 있을 때만.

## 순서
1. 화면 하나 + 가짜 데이터로 핵심 흐름이 도는 판 → Browser 미리보기 확인
2. 실제 데이터·로직 연결
3. 입력 검증·오류 메시지
4. 나머지 화면

## 검증
- 서버: `0.0.0.0` 바인딩, 실행 포트 출력. Browser 탭에 포트·경로 입력 후 원형 화살표.
- API 는 `curl -s localhost:<포트>/<경로>` 로 응답을 터미널에 남긴다(증거가 기록에 남는다).
- 핵심 흐름을 사용자가 Browser 에서 직접 눌러 보게 하고 결과를 `log_work`.

## 함정
- `localhost`/`127.0.0.1` 바인딩 → 미리보기 안 됨
- 서버를 띄운 터미널 탭을 닫아 프로세스 종료
- 외부 CDN 스크립트(네트워크 막힘 가능) → 필요하면 로컬 파일로
- 오류를 콘솔에만 찍고 화면에는 정상처럼 보이는 것
