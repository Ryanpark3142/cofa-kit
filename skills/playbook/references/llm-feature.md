# 결과물 안의 LLM 기능 (요약·분류·추출·챗봇)

## 먼저 확인
- 결과물이 호출할 수 있는 모델·엔드포인트·키가 **환경에서 제공되는지** 지시서·담당자에게 확인한다. 개인 API 키는 쓰지 않는다. 키는 환경 변수로만, 파일에 쓰지 않는다.
- 제공되지 않으면: 규칙 기반·키워드 기반으로 먼저 만들고, LLM 호출부는 인터페이스만 두고 가짜 응답(mock)으로 동작시키는 방안을 담당자에게 제안한다.

## 최소 구조
- LLM 호출은 함수 하나로 감싼다: `classify(text) -> {label, reason}`. 프롬프트는 상수로 한곳에.
- 출력은 JSON 등 구조화 형식으로 요청하고, 파싱 실패 시 재시도 1회 → 실패 표시(정상값처럼 숨기지 않기).
- 실패·시간 초과 때 사용자가 보는 화면/결과를 정한다.

## 검증
- 정답을 아는 예시 10~20개로 정확도를 잰다(담당자 예시가 있으면 그것). 수치를 보고서에.
- 경계 사례(애매한 입력, 빈 입력, 아주 긴 입력) 확인.

## 함정
- 응답 형식이 매번 달라 파싱 실패
- 비용·지연을 고려하지 않은 반복 호출(캐시는 요구가 있을 때만)
- 개인정보를 그대로 프롬프트에 넣기
