# check — 독립 검증 (검증 세션)

같은 AI 가 같은 코드를 다시 읽고 "맞다" 고 하는 것은 검증이 아니다. 제품 코드의 계산을 가져다 쓰지 않고 다른 길로 같은 결과를 내 본다. 이 세션은 제품 코드를 고치지 않는다.

## 순서
1. `node .cofa/kit/scripts/kit.mjs board` 와 REQUIREMENTS.md 를 본다. 사용자가 대상을 말하지 않았으면 「구현(미검증)」 요구 2~3개를 고른다.
2. 요구마다 한 줄: 입력 → 기대 결과 → 독립적으로 구하는 방법(작은 표본 손계산, 원자료 직접 집계, 다른 라이브러리·쿼리, 지시서·담당자가 준 예시).
3. 검증 스크립트는 `checks/` 폴더에만 쓴다. 제품 코드를 import 하지 않고 제품의 출력(파일·CLI 출력·HTTP 응답)만 읽어 비교한다. 다르면 0 이 아닌 종료 코드로 끝나게 쓴다.
4. 실행 전에 예상 결과 한 줄 → `node .cofa/kit/scripts/kit.mjs run --req <ID> --mark verified -- <검증 명령>`. 통과하면 그 요구가 「검증됨」 으로 오른다.
5. 엣지 케이스(빈 입력·경계값·잘못된 형식·중복·큰 입력)도 같은 방식으로 1~3개.
6. 불일치는 고치지 않는다. 원인을 셋 중 하나로 나눠 보고한다: 제품 오류 / 검증 스크립트 오류 / 요구 해석 차이(→ 담당자 질문 후보).
7. `checks/` 만 커밋: `node .cofa/kit/scripts/kit.mjs commit -m "test: <요구 ID> 독립 검증" checks/<파일…>`

## 보고
| 요구 | 독립 방법 | 기대 | 실제 | 판정 | 증거 |
그 아래에 불일치와 분류, 메인에 넘길 일. 결과를 부풀리지 않는다.

## 하지 않는 것
- 제품 코드 수정, 테스트를 통과하게 기대값 바꾸기, 패키지 설치, 서버 띄우기(메인이 띄운 서버에 curl 은 된다)
