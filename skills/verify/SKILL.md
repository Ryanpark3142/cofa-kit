# verify — 증거로 확인 (메인 세션)

같은 AI 가 "맞다" 고 다시 말하는 것은 검증이 아니다. 명령을 실행한 결과, 손으로 계산한 기대값과의 비교, 다른 경로로 낸 같은 숫자만 증거다.

## 순서
1. `node .cofa/kit/scripts/kit.mjs board` 로 「구현(미검증)」 요구를 본다. 시간이 30분 넘게 남았으면 사용자에게 다른 탭의 `$check`(독립 재계산)를 권하고, 메인은 아래를 한다.
2. 요구마다:
   - 확인 방법(명령 · 입력 → 기대 출력)을 정하고, **실행 전에** 예상 결과를 한 줄로 적는다. 예상과 실제가 다르면 그 차이가 발견이다.
   - `node .cofa/kit/scripts/kit.mjs run --req <ID> --mark verified -- <명령>` — 통과하면 「검증됨」 과 증거 번호가 자동으로 남는다.
   - 실패·미실행이면 상태를 그대로 두고 이유를 보고한다.
3. **빈 통과 점검**: 테스트·검사가 0건을 대상으로 돌지 않았는지(입력 행 수, 테스트 개수, 매칭 건수)를 출력으로 확인한다. kit.mjs 는 흔한 0건 문구를 「0건(돌리지 않음)」 으로 잡지만, 직접 만든 스크립트는 처리 건수를 출력하게 한다.
4. **엣지 케이스** 3~5개: 빈 입력, 경계값, 잘못된 형식, 중복, 큰 입력(시간 측정). 고칠 시간이 없으면 한계로 적는다.
5. **실패 경로**: 오류·예외 때 사용자가 실제로 보는 결과(화면 메시지, 출력 파일)를 확인한다. 대체값이 정상처럼 보이게 숨지 않는지 본다.
6. **핵심 숫자 교차 확인**(데이터 과제): 주요 집계 1~2개를 다른 방법(다른 코드 경로, 작은 표본 손계산)으로 다시 낸다.
7. `kit.mjs check` 가 「마지막 통과 뒤에 코드가 바뀜」 을 내면 해당 명령을 다시 돌린다.
