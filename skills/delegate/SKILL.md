# delegate — 작업 나누기 (메인 세션)

위임의 가치는 「맡길 일과 검증 고리를 먼저 설계」 하는 데 있다. 범위가 흐린 일은 맡기지 않는다. 동시에 맡기는 작업은 2개까지.

## 맡겨도 되는 일
- 파일이 겹치지 않는 독립 모듈, 테스트 작성, 데이터 변환 스크립트, 문서 초안
- 완료 기준을 명령 하나로 확인할 수 있는 일

## 맡기면 안 되는 일
- 요구가 아직 모호한 일, 메인 작업과 같은 파일을 고치는 일, 설계 결정, 패키지 설치가 필요한 일

## 맡기기
1. 작업 파일을 만든다(번호는 자동, 다른 작업과 파일이 겹치면 경고가 나온다):
   ```bash
   node .cofa/kit/scripts/kit.mjs task new "<제목>" --files "<src/a.py,tests/test_a.py>" --done "<완료 기준 명령>" --req <R2> --goal "<한 줄>"
   ```
2. 생긴 `.cofa/tasks/T<n>.md` 의 「입출력 계약」 을 2~3줄 채운다(함수 이름·인자·반환, 파일 형식, 예시 입력 → 기대 출력). 작업 세션은 이 파일만 보고 일한다.
3. 사용자에게 그대로 안내한다:
   > 터미널 새 탭(+) → `codex` → `/permissions` → `Full Access` → `$worker T<n>`
   탭을 열기 번거로운 짧은 일이면 이 세션의 서브에이전트에게 맡겨도 된다: 「T<n> 을 서브에이전트에게 맡겨서 `.agents/skills/worker/SKILL.md` 절차대로 하게 해줘」.
4. 그동안 메인은 다른 슬라이스·담당자 질문·검증을 한다. 맡긴 파일은 고치지 않는다.

## 돌아온 결과 (작업이 「완료」 가 되면)
1. `.cofa/tasks/T<n>.md` 의 「결과」 를 읽는다.
2. `git show --stat <커밋>` 으로 허용 파일만 바뀌었는지 본다(커밋 못 했으면 `git diff --stat -- <허용 파일>`).
3. 완료 기준 명령을 메인에서 **직접 다시** 돌린다: `kit.mjs run --req <ID> -- <완료 기준 명령>`.
4. 「메인이 할 일」 이 있으면 처리한다(라우터 등록 등). 작업 세션이 커밋을 못 했으면 `kit.mjs commit -m "feat: … (T<n>)" <허용 파일…>`.
5. `node .cofa/kit/scripts/kit.mjs task T<n> 검증됨`, 한 줄 기록: `kit.mjs log "T<n> 위임 → 메인 재검증 통과(증거 #N)"`.

## 비상: 탭·서브에이전트가 둘 다 안 될 때
새 터미널에서 비대화형으로: `codex exec -s workspace-write -C "$PWD" "\$worker T<n>"`. 결과는 작업 파일의 「결과」 절에 남는다. 커밋을 못 했으면 메인이 위 4번으로 커밋한다.
