# delegate — 위임과 병렬 작업

위임의 가치는 "맡길 일과 검증 고리를 먼저 설계"하는 데 있다. 범위가 흐린 일은 맡기지 않는다.

## 맡겨도 되는 일
- 파일이 겹치지 않는 독립 모듈, 테스트 작성, 데이터 변환 스크립트, 문서 초안
- 완료 기준을 명령 하나로 확인할 수 있는 일

## 맡기면 안 되는 일
- 요구가 아직 모호한 일, 메인 작업과 같은 파일을 고치는 일, 설계 결정

## 방법 (위에서부터 되는 것을 쓴다)
1. **Codex 서브에이전트**: 같은 세션에서 "T1 지시서를 서브에이전트에게 맡기고, 그동안 나는 ~를 하자"라고 요청한다(최근 Codex 는 multi_agent 가 기본 켜짐). 결과는 메인 세션이 받는다.
2. **새 터미널(+)에서 비대화형 실행**: 쓰기 권한을 명시해야 한다. `codex exec` 는 승인 창을 띄울 수 없어서 샌드박스가 읽기 전용이면 아무것도 못 쓰고 끝난다.
   ```bash
   codex exec -s workspace-write -C "$PWD" -o .cofa/tasks/T1.result.md "$(cat .cofa/tasks/T1.md)"
   ```
   검증만 맡길 때는 `-s read-only` 로 돌린다(코드를 못 바꾸게). Codex 안에서 `codex exec` 를 다시 부르는 중첩 실행은 시험 환경에서 확인된 적이 없으니, **사람이 새 터미널에서 직접** 실행한다. 결과 요약은 `.cofa/tasks/T1.result.md` 에 남는다. 서버를 띄운 터미널 탭에서는 실행하지 않는다.
3. 위 둘이 안 되면 새 터미널에서 `codex` 를 열고 지시서를 붙여 넣는다.

## 위임 지시서 (`.cofa/tasks/T<n>.md`)
```
# T<n>: <제목> (요구 ID)
목표: 한 줄
수정 가능한 파일: a.py, tests/test_a.py  (이 밖은 건드리지 말 것)
입력/출력 계약: 함수 시그니처 또는 파일 형식
완료 기준: `<명령>` 이 통과
하지 말 것: 커밋, 다른 파일 수정, 패키지 설치
끝나면: 변경 파일 목록과 완료 기준 명령의 실제 출력만 보고
```

## 돌아온 결과
1. `git diff --stat` 로 허용 파일만 바뀌었는지 본다.
2. 완료 기준 명령을 메인 세션에서 **직접 다시 실행**한다.
3. 통과하면 `req_upsert`, `log_work`("T1 위임 → 검증 통과"), 커밋.
