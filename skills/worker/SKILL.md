# worker — 맡은 작업 하나 (작업 세션)

이 세션은 메인이 아니다. 다른 탭의 메인 세션·작업 세션이 같은 폴더를 동시에 고치고 있다. 작업 파일의 범위 안에서는 묻지 않고 끝까지 한다.

## 순서
1. `.cofa/tasks/T<n>.md` 를 읽는다. 번호를 못 받았으면 `node .cofa/kit/scripts/kit.mjs task list` 를 보여 주고 어느 작업인지 묻는다.
2. `node .cofa/kit/scripts/kit.mjs task T<n> 진행`
3. 「수정 가능한 파일」 과 그 파일이 부르는 코드만 읽는다. 할 일 3줄(무엇 · 어느 파일 · 어떻게 확인).
4. 완료 기준을 테스트로 먼저 쓴다(테스트 파일이 허용 목록에 있을 때). 구현은 최소한으로.
5. 허용 파일 밖을 고쳐야 하면 고치지 않고 「메인이 할 일」 로 적는다(예: 라우터에 한 줄 등록, 패키지 추가).
6. 실행 전에 예상 결과 한 줄 → `node .cofa/kit/scripts/kit.mjs run --req <요구 ID> -- <완료 기준 명령>`. 실패하면 원인부터 확인한다(`$debug` 방식). 같은 수정이 두 번 실패하면 멈추고 결과에 적는다.
7. 통과하면 허용 파일만 커밋: `node .cofa/kit/scripts/kit.mjs commit -m "feat: <무엇> (T<n>, <요구 ID>)" <허용 파일…>`. 커밋이 막히면(샌드박스) 결과에 「커밋 못 함」 으로 적는다 — 메인이 커밋한다.
8. 작업 파일(`.cofa/tasks/T<n>.md`) 맨 아래 `## 결과` 의 안내 문장을 5줄로 바꿔 쓴다: 바꾼 파일 · 증거 번호와 결과 · 커밋 해시(또는 「커밋 못 함」) · 메인이 할 일 · 남은 문제. 이 절은 허용 파일 목록과 상관없이 작업 세션이 쓰는 곳이다(메인이 이걸 보고 다시 확인한다). 그다음 `kit.mjs task T<n> 완료`.
9. 사용자에게 같은 5줄과 「흐름」 한 줄(실제 입력값 하나 → 파일:함수 → 출력값, 예: `EQ-D 2000/1699` → `report.mjs:summarize()` → `84.95% WARN`)을 보고하고 끝낸다. 다른 작업을 스스로 고르지 않는다.

## 하지 않는 것
- 허용 파일 밖 수정, 패키지 설치, 서버 띄우기, 설계 변경(필요하면 결과에 제안으로)
- PLAN.md·SUBMISSION.md·EXPLAIN.md 직접 수정(메인·공부 탭 몫). 계약이 비어 있어 스스로 정한 구현 선택은 `kit.mjs decision` 으로 남기고 결과에 적는다
- `git add -A`·`git add .`·`git commit -a`·`git stash`·`git reset`·`git checkout -- .`·`git clean` — 다른 탭의 작업을 쓸어 가거나 지운다
- 테스트가 같은 파일·포트·DB 를 다른 탭과 함께 쓰게 만들기(임시 폴더·다른 이름을 쓴다)
