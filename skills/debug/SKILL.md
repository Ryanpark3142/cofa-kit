# debug — 원인부터

1. **재현**: 실패를 만드는 가장 짧은 명령을 찾아 실행하고 오류 원문(마지막 20줄 이내)을 보여준다.
2. **가설 2~3개**: 각각 근거(오류 줄·데이터·최근 변경)와 "이 가설이 맞으면 보일 것"을 적는다.
3. **판별 실험**: 가설을 가르는 가장 싼 확인(print·작은 입력·`git diff`·버전 확인)부터 실행한다. 코드는 아직 안 고친다.
4. **최소 수정**: 원인이 확인된 것만 고친다. 고친 뒤 1번 명령과 기존 테스트를 다시 돌린다.
5. **기록**: `node .cofa/kit/scripts/kit.mjs log "원인: ~ / 수정: ~ / 확인: 증거 #N"`. 같은 종류가 또 나올 수 있으면 테스트를 하나 추가한다.

## 멈춤 규칙
- 같은 가설로 2번 실패하면 접근을 바꾸거나 사용자에게 상황(시도한 것·결과·남은 가설)을 보고한다.
- 10분 넘게 막히면 `kit.mjs status` 를 보고 우회안(기능 축소·대체 구현)을 제안한다.
- 다른 탭이 같은 시각에 바꾼 파일 때문일 수 있다: `git log --oneline -5` 와 `kit.mjs board` 를 먼저 본다.
- 환경 문제(패키지·포트·메모리)는 `kit.mjs env`, 우측 상단 CPU/RAM 을 먼저 본다. 플랫폼 오류가 반복되면 사용자에게 「문제 신고」 를 권한다.
