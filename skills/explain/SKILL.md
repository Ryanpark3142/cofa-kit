# explain — 사용자가 이해하게 설명하기

목표는 사용자가 **AI 없이 자기 말로** 결과물을 설명하는 것이다(과제 뒤 서술형). 설명을 읽고 「이해했다」 고 느끼는 것은 믿을 수 없다. 확인은 사용자가 직접 떠올려 말하는 것으로만 한다.

이 스킬은 제품 코드를 고치지 않는다. 쓰는 파일은 `EXPLAIN.md` 하나뿐이다. 다른 탭에서 쓰고 있으면 먼저 `git log --oneline -5` 와 바뀐 파일만 보고(다른 탭이 방금 바꾼 코드일 수 있다), 사용자가 고른 파일·질문부터 설명한다.

## 설명하는 방식
1. **원리 한 문장 먼저, 구체는 그다음.** 「왜 이렇게 되나」 를 한 문장으로 말한 뒤에 파일·함수·명령을 댄다. 그러면 세부가 결론으로 읽힌다.
2. **실제 값 하나로 따라간다.** 일반론 대신 입력 하나를 넣어 처음부터 끝까지 따라간다. 예: `POST /todos {"title":"우유"}` → `app.py:create_todo()` 가 제목 검사 → `todos` 리스트에 `{id:1}` 추가 → 201 응답. 데이터 과제면 행 2~3개로 계산을 손으로 보여 준다. 그다음에 일반화한다.
3. **처음 보는 것은 표가 아니라 문장으로.** 표는 이미 아는 것을 찾아볼 때 쓴다.
4. **처음 나오는 용어는 그 자리에서 한 줄 정의.** 라이브러리·프로토콜·옵션 이름도 용어다(예: `0.0.0.0` = 「이 컴퓨터의 모든 네트워크 입구에서 받기」). 사용자가 「○○가 뭐야」 라고 물으면 첫 문장을 정의로 답한다. 정의한 용어는 `EXPLAIN.md` 「용어」 에 한 줄씩 모은다.
5. **비유는 한 줄, 그다음 실제 용어로 다시.** 비유만으로 끝내지 않는다.
6. **한 토막씩.** 한 번에 개념 하나, 5~8줄. 더 필요하면 사용자가 묻게 한다.
7. **「어디에 쓰이나」 한 줄.** 업무 맥락(담당자가 이 결과로 무엇을 하나)에 붙인다.

## 확인 질문
- **사용자의 되묻기가 멎고 그 개념이 끝났을 때 하나만** 낸다. 궁금증이 남아 있는 동안 퀴즈를 끼우지 않는다. 구현이 진행 중일 때(명령 실행·승인 대기 중)에는 내지 않는다.
- 형식은 **빈칸 하나나 선택지**다. 「무엇이고 어디로 가서 어떻게 되나」 같은 조립형은 쓰지 않는다. 기계적으로 계산하면 되는 칸은 묻지 않고 **판단이 갈리는 칸**만 묻는다.
  - 예: 「제목이 빈 문자열이면 `create_todo()` 는 ___ 를 돌려준다.」
  - 예: 「목록을 메모리 리스트에 둔 이유는? ①요구에 영속 저장이 없어서 ②빨라서 ③DB 설치가 막혀서」
- **질문을 냈으면 거기서 말을 끝낸다.** 예시 답·힌트·둘째 질문을 붙이지 않는다. 붙여도 되는 말은 「틀려도 돼」 「넘어가도 돼」 뿐이다.
- 답을 받으면 확실 / 흔들림(힌트 받고 맞힘) / 빈칸(틀림) 으로 매긴다. 틀렸으면 **처음 틀린 줄 하나**만 짚고 2번(실제 값 따라가기)으로 다시 보여 준다. 흔들림·빈칸은 `EXPLAIN.md` 「다시 볼 것」 에 넣고, `$explainback` 이 제출 전에 다시 묻는다.
- 사용자가 「패스」 하면 바로 넘어가고 「다시 볼 것」 에 `패스` 로 남긴다.

## 결정을 기록할 때
사용자가 설계안에 「응」 「그걸로」 라고만 답했으면, 그 결정과 이유를 사용자가 **한 줄로 다시 말하게** 한 뒤 그 문장을 `DECISIONS.md` 에 옮긴다(동의만으로는 서술형에서 설명이 안 나온다). 시간이 급하면 사용자가 「패스」 할 수 있다.

## 공부 탭에서 쓸 때 (구현을 기다리는 동안)
1. 사용자가 고른 슬라이스·파일의 흐름을 **실제 값 하나로** 따라간다: 입력 → 파일:함수 → 출력. 메인 보고의 「흐름」 줄이 출발점이다.
2. 처음 나온 용어는 한 줄 정의하고 `EXPLAIN.md` 「용어」 에 모은다.
3. `EXPLAIN.md` 맨 위 A/B/C 3줄을 갱신한다(`$explainback` 참고). 사용자가 직접 본 것만 `(내가 봄)`.
4. 사용자가 원하면 확인 질문 하나. 흔들리거나 틀린 것은 「다시 볼 것」 에 남긴다.

## 하지 않는 것
- 사용자가 읽지 않을 긴 설명문, 같은 내용의 반복 요약.
- 사용자가 「이해했어」 라고 한 것만으로 넘어간 개념을 「설명 가능」 으로 기록하기.
- 사용자가 스스로 떠올려야 할 답을 질문과 함께 흘리기.
