# plan — 설계와 슬라이스

## 순서
1. `req_list` 와 `time_status` 를 본다. 남은 시간 안에 필수 요구를 끝낼 수 있는 크기로만 계획한다.
2. **설계안 2개**를 표로 비교한다: 구조 한 줄 · 쓰는 기술(이미 설치된 것 우선) · 장점 · 위험 · 예상 시간. 추천 하나와 이유. **사용자가 고른다.**
3. 선택을 `log_decision` 으로 남긴다(버린 대안·이유·검증 방법 포함).
4. **슬라이스 분할**: 첫 슬라이스는 "입력에서 출력까지 가장 얇게 도는 판"(walking skeleton). 이후 슬라이스는 요구 ID 단위.
5. 슬라이스마다 **검증 방법을 먼저** 적는다: 어떤 입력 → 기대 출력, 실행 명령. 작은 손계산 예제나 담당자가 준 사례를 기대값으로 쓴다.
6. **과설계 점검**: 각 구성요소에 "어느 요구 ID 때문인가?"를 붙인다. 답이 없으면 뺀다(DB 대신 파일, 프레임워크 대신 표준 라이브러리로 되는지 먼저).
7. PLAN.md 를 채우고 커밋을 제안한다.

## PLAN.md 형식
```
# PLAN
## 목표 (한 줄)
## 완료 기준 (요구 ID별, 측정 가능하게)
## 선택한 구조 (한 단락) — 근거: DECISIONS.md
## 슬라이스
| # | 내용 | 요구 ID | 검증(입력→기대 출력, 명령) | 예상 분 |
## 하지 않을 것 (범위 밖, 이유)
## 위험과 대비
```

## 시간 규칙
- 계획에 15분 넘게 쓰지 않는다.
- 슬라이스 합계가 남은 시간의 70%를 넘으면 뒤쪽 슬라이스를 「여유 시 진행」 으로 내린다.
