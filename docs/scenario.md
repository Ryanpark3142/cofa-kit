# 당일 시나리오 — 무엇을 어디에 입력하나

표기: **[터미널]** IDE 아래 터미널에 직접 친다 · **[Codex]** `codex` 화면에 입력 · **[메신저]** 오른쪽 담당자 DM · **[나]** 사람이 직접 할 일.
예시 과제는 「설비별 수율 경고 도구」(CSV 를 읽어 설비별 평균 수율을 내고 기준 미만을 경고)로 든다. 실제 과제에 맞게 `<>` 를 바꾼다.

## 스킬 이름을 외울 필요는 없다
- `$kickoff` 같은 것은 「이 일은 이 절차로」 를 담은 **스킬**을 이름으로 부르는 문법이다. 아래 시나리오는 확실하게 하려고 이름을 썼을 뿐이다.
- **말로 해도 된다**: 「과제 파악부터 하자」 → Codex 가 kickoff 를 스스로 고른다(codex-cli 0.164 실측).
- **「다음」 만 쳐도 된다**: `next` 스킬이 시간·진행 기록을 보고 지금 단계를 골라 진행한다(실측). 결정이 필요한 곳(설계안 선택, 질문 보내기, 고칠 것 고르기)에서만 멈춘다.
- 목록이 궁금하면 `$` 만 치거나 `/skills`.
- 사람이 반드시 직접 하는 것: README 정독, 담당자에게 질문 보내기·답 붙여넣기, 설계안 고르기, Browser 에서 눌러 보기, 서술형 연습 답 쓰기, 제출 버튼.

## 0분 — 과제 시작 직후 (3분)

**[나]** 「과제 시작」 → 휴대폰 거치·신분증 확인을 마친다. README 를 열어 두기만 하고 아직 읽지 않는다.

**[터미널]** `codex` 를 열고 **[Codex]** 에 한 문장(외울 것은 주소 `Ryanpark3142/cofa-kit` 하나):
```
github.com/Ryanpark3142/cofa-kit 를 /tmp/kit 에 받아서 README 대로 설치해줘
```
인터넷 접근 승인 창이 뜨면 승인한다. 끝나면 `codex` 를 닫고 다시 연다(규칙·스킬은 세션 시작 때 읽힘).

Codex 가 엉뚱하면 **[터미널]** 에 직접:
```bash
git clone https://github.com/Ryanpark3142/cofa-kit /tmp/kit && bash /tmp/kit/install.sh
```
- clone 이 막히면:
  ```bash
  mkdir -p /tmp/kit && curl -fsSL https://codeload.github.com/Ryanpark3142/cofa-kit/tar.gz/refs/heads/main | tar xz -C /tmp/kit --strip-components=1 && bash /tmp/kit/install.sh
  ```
- 출력 끝의 MCP JSON 을 **[나]** 왼쪽 MCP 탭에 붙이고 저장한다(선택. 안 되면 건너뛴다).

**[터미널]** `codex` → 폴더 신뢰를 물으면 신뢰 → `/model` 에서 **gpt-6.1-sol · medium** 선택.
(홈이 아닌 폴더에 설치돼 훅이 생겼다면 `/hooks` 에서 cofa-kit 훅 2개 신뢰.)

**[Codex]** 키트가 읽혔는지 확인 (한 번만):
```
파일을 열지 말고, 지금 받은 지침에 있는 cofa-kit 원칙 6개의 제목과 쓸 수 있는 스킬 이름만 말해줘.
```
→ 원칙·스킬 이름이 나오면 OK. 「모른다」면 `AGENTS.md 를 읽고 앞으로 따라줘.` 한 줄로 대신한다.

## 30~130분 — 구현 (슬라이스 반복)

슬라이스마다 같은 패턴:

**[Codex]**

**[나]** 결과 보고에서 확인할 것: 「증거 #번호 · 통과」 가 있는지, 「미검증」 이 무엇인지.
웹이면 **[나]** 왼쪽 Browser 탭에 Codex 가 알려준 포트·경로를 넣고 직접 눌러 본다. 그리고:
```

**이해 확인 (슬라이스마다 30초, 서술형 대비):**
```

```
→ 내가 이해 못 한 줄이 있으면 그 자리에서 묻는다.

**막혔을 때:**
```

```
같은 방법으로 두 번 실패하면:
```

→ 서브에이전트로 맡기거나, **[터미널]** 새 탭(+)에서:

**시간 체크포인트:**

## 서술형 (AI·복붙 금지, 문항당 5분, 6문항)

틀: **무엇을 했나(파일·함수) → 왜(버린 대안·담당자 답) → 어떻게 검증했나(증거 번호·수치) → 한계·다음 개선.**
질문 전제가 실제와 다르면 첫 줄에 「실제로는 ~ 했습니다」.
예시 (질문: 「경고 기준을 어떻게 정했고 어떻게 확인했나요?」):
```
yield-report.mjs 의 classify() 에서 평균 수율 85 미만을 경고로 판정했습니다. 85 는 담당자 박 매니저에게 "85 와 같으면 정상인가"를 직접 물어 확정했고,
처음엔 85 이하로 하려다 답을 받고 미만으로 바꿨습니다. 84.9·85·85.1 경계 테스트를 만들어 kit.mjs run 증거 #4 에서 9개 테스트가 통과했습니다.
한계는 기준값이 코드 상수라 바뀌면 수정이 필요하다는 점이고, 다음엔 설정 파일로 빼겠습니다.
```
