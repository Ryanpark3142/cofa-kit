# 당일 시나리오 — 무엇을 어디에 입력하나

표기: **[터미널]** IDE 아래 터미널에 직접 친다 · **[Codex]** 메인 탭의 `codex` 화면에 입력 · **[탭2]** **[탭3]** 터미널 `+` 로 연 다른 탭의 `codex` · **[메신저]** 오른쪽 담당자 DM · **[나]** 사람이 직접 할 일.
예시 과제는 「설비별 수율 경고 도구」(CSV 를 읽어 설비별 수율을 내고 기준 미만을 경고)로 든다. 실제 과제에 맞게 `<>` 를 바꾼다.

## 탭 세 개를 이렇게 쓴다
| 탭 | 언제 연다 | 하는 일 |
|---|---|---|
| 메인 | 처음부터 | 파악·담당자 질문·계획·결정·통합·제출. 나머지 탭에 일을 나눠 준다 |
| 탭2 작업 | 메인이 `$delegate` 로 T 파일을 만들었을 때 | `$worker T1` — 그 파일만 고치고 테스트·커밋 |
| 탭3 검증·공부 | 시작부터 끝까지 | `$explain`(과제 → 계획 → 단계별 → 전체 정리, 이어 듣기는 `ㄱ`) · `$check`(독립 검증) · `$explainback`(설명 연습) |
- Codex 가 슬라이스 하나에 1~2분씩 일하는 동안 나는 탭3 에서 공부한다. 기다리는 시간이 서술형 준비 시간이 된다.
- 탭은 3개까지. 같은 파일을 두 탭이 고치지 않는다(작업 파일이 나눠 준다). 지금 상태는 어느 탭에서나 `node .cofa/kit/scripts/kit.mjs board`.
- 실측(codex-cli 0.164, gpt-6.1-sol): 슬라이스 구현 77~91초, 작업 탭과 검증 탭을 동시에 돌려도 기록·증거 번호가 섞이지 않았다.

## 스킬 이름을 외울 필요는 없다
- `$kickoff` 같은 것은 「이 일은 이 절차로」 를 담은 **스킬**을 이름으로 부르는 문법이다. 아래 시나리오는 확실하게 하려고 이름을 썼을 뿐이다.
- **말로 해도 된다**: 「과제 파악부터 하자」 → Codex 가 kickoff 를 스스로 고른다(codex-cli 0.164 실측).
- **「다음」 만 쳐도 된다**: `next` 스킬이 시간·진행 기록을 보고 지금 단계를 골라 진행한다(실측). 결정이 필요한 곳(설계안 선택, 질문 보내기, 고칠 것 고르기)에서만 멈춘다.
- 목록이 궁금하면 `$` 만 치거나 `/skills`.
- 사람이 반드시 직접 하는 것: README 정독, 담당자에게 질문 보내기·답 붙여넣기, 설계안 고르기, Browser 에서 눌러 보기, 서술형 연습 답 쓰기, 제출 버튼.

## 서술형 (AI·복붙 금지, 문항당 5분, 6문항)

틀: **무엇을 했나(파일·함수) → 왜(버린 대안·담당자 답) → 어떻게 검증했나(증거 번호·수치) → 한계·다음 개선.**
질문 전제가 실제와 다르면 첫 줄에 「실제로는 ~ 했습니다」.
예시 (질문: 「경고 기준을 어떻게 정했고 어떻게 확인했나요?」):
```
yield-report.mjs 의 classify() 에서 평균 수율 85 미만을 경고로 판정했습니다. 85 는 담당자 박 매니저에게 "85 와 같으면 정상인가"를 직접 물어 확정했고,
처음엔 85 이하로 하려다 답을 받고 미만으로 바꿨습니다. 84.9·85·85.1 경계 테스트를 만들어 kit.mjs run 증거 #4 에서 9개 테스트가 통과했습니다.
한계는 기준값이 코드 상수라 바뀌면 수정이 필요하다는 점이고, 다음엔 설정 파일로 빼겠습니다.
```

## 비상 상황

| 상황 | 할 일 |
|---|---|
| clone·curl 둘 다 안 됨 | 키트 없이 진행. **[Codex]** 첫 줄에 「요구 등록 → 계획 → 작은 단위 구현·테스트·커밋 → 검증 → 제출 문서 순서로, 요구에 없는 기능은 만들지 말고, 실행한 것만 말해줘」 |
| 승인 창이 계속 뜸 | `/permissions` → `Full Access` 를 이 탭에서 골랐는지 확인. 그래도 뜨면 승인 창마다 `p`(같은 명령 다시 묻지 않기) |
| 스킬(`$kickoff`)을 모른다고 함 | `.agents/skills/kickoff/SKILL.md 를 읽고 그 절차대로 해줘.` |
| `index.lock` 오류 | 다른 탭이 커밋 중이다. `kit.mjs commit` 은 잠시 뒤 스스로 다시 한다 |
| 두 탭이 같은 파일을 고쳤다 | `git diff <파일>` 로 보고 메인이 합친다. 이후 그 파일은 한 탭만 |
| 탭을 실수로 닫음 | 새 탭에서 `codex resume` → 그 대화를 고른다 |
| 응답이 너무 느림 | 추론 강도 확인(`/model`), 긴 대화면 `$handoff` |
| 화면·감독 오류 | 상단 「문제 신고」에 시각·증상. Codex 로 해결하려 하지 않는다 |
| 15분 남음 | `새 기능은 멈추고 저장·커밋·제출 문서만 해줘. $submit` |
