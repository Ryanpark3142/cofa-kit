# 당일 운영표

과제 180분 + 사후 설명(서술형) 기준. 실제 시험 안내와 다르면 안내를 따른다. 무엇을 어디에 입력하는지는 `scenario.md`, 시험 중 한 장 요약은 `node .cofa/kit/scripts/kit.mjs card`.

이 키트 저장소(`Ryanpark3142/cofa-kit`)는 **결과 통지 전까지 공개 상태로 둔다**(2026-10-29 메일 조건). 시험 후에도 비공개로 돌리거나 지우지 않는다.

## 사전 체험에서 직접 본 것 (2026-10-31 0시대)
- **전체 화면을 벗어나면 기록된다.** 다른 창으로 2초 이동(스크린샷 도구 포함)에 「규정 위반 1회 — 평가자에게 전달」 경고가 떴다. 본시험에서는 캡처·창 전환을 하지 않는다. 키트 문서는 IDE 안(에디터·터미널 `kit.mjs card`)에서만 본다.
- 설치: Codex 에 「github.com/Ryanpark3142/cofa-kit 을 README 대로 설치해줘」 → `git clone` 네트워크 승인 1번, `install.sh` 실행 승인 1번 → 성공. **저장소 이름을 틀리면 「GitHub 인증 필요」 로 실패한다**(체험 때 `cofa-kid` 오타). 주소는 그대로 쳐 넣는다.
- 작업 폴더는 홈(`~`). 그래서 훅은 설치되지 않았다(설계대로). MCP 탭에는 `{"mcpServers": {}}` 가 비어 있다.
- 기본 모델 표시 `GPT-6.1-Sol default`. `npm i -g @openai/codex` 는 EACCES 로 막힌다(Codex 업데이트 불가, 시도하지 않는다).
- Codex 샌드박스에서 외부 주소는 DNS 부터 안 된다(`curl developers.openai.com` → exit 6). 문서 조회에 기대지 않는다.
- Codex 가 확인한 제한: `~/.codex/config.toml` 수정 금지, **관리 포트 8090·8081·2222 사용 금지**, 앱은 다른 포트에 `0.0.0.0`, git push 금지.
- 승인 창에는 `2. Yes, and don't ask again for commands that start with … (p)` 가 있다. Full Access 를 못 쓰면 반복 명령은 처음 한 번 `p` 로 승인한다.
- 승인을 통째로 줄이는 방법: 탭마다 세션 안에서 `/permissions` → `Full Access`(사용자가 가능함을 확인, 2026-11-05). 샌드박스를 끄는 실행 옵션은 쓰지 않는다.
- 터미널은 `+` 로 탭을 여러 개 열 수 있다 → 탭마다 Codex 세션을 따로 띄울 수 있다.
- Cofa Helper 는 플랫폼 사용법만 답하고 과제 풀이·코드 리뷰는 하지 않는다.
- 확인 문제: 2문항, 문항당 약 3분 타이머, 복사·붙여넣기 불가, 시간이 끝나면 자동 확정, 이전 문항으로 못 돌아감. 1번 「체험 과제에서 구현한 서비스의 핵심 동작과 이를 확인한 방법을 설명해 주세요.」
- 상단 자원 표시는 `558M/16G`(공개 후기의 1.6GB 와 다름). 그래도 서버는 하나만, 탭은 3개까지.

## 공개 후기에서 본 환경 (다른 응시자 저장소, 사전 체험 관찰. 본시험과 다를 수 있음)
- 작업 폴더는 홈(`/home/user`)이고 홈 자체가 git 저장소. 이때 install.sh 는 `~/.codex` 보호를 위해 훅을 설치하지 않는다(훅은 `--hooks` 일 때만 설치하고, 그때도 홈이면 건너뛴다).
- `python` 없음, `python3` 있음. Node 22·git 2.39 계열.
- 서버 실행에 승인 창이 뜰 수 있고, 1024 미만 포트는 거부.
- 공개 저장소 clone 은 됨(승인이 필요할 수 있음). git push 는 막힘.
- 체험 서술형: 「만든 것이 무엇을 하며 어떻게 확인했나」, 「AI 제안을 어떻게 확인·수정했나」.
- 응시 메신저에는 Cofa Helper 없이 과제 담당자만 있을 수 있다(출처 불명확).

## 본시험 1회차 관찰 (2026-10-31, 응시 환경 문제로 재시험 예정)
- 과제 모양: CSV 데이터셋(구성원·정류장·근무표)을 고르고 검증·적용 → 노선 생성(정원·도착 여유 조건) → 구성원 화면 조회·내보내기. 「정류장별 직행이나 차량 수만 줄이는 병합」 이 아닌 방식을 요구. Docker 컨테이너 실행, 제출물에 `AI_COLLABORATION.md`.
- 서술형 6문항(문항당 5분, 「제출 전 이해도 확인」). 1 알고리즘 선택 근거·대안·한계 / 2 데이터 흐름 모듈과 상태 저장·소유 / 3 구현·검증한 것 vs 가정, 평가자 확인 경로 / 4 기록 없음 / 5 데이터·조건이 바뀔 때 추가 검증과 AI 결과 판단 근거 / 6 `AI_COLLABORATION.md` 에 적은 Docker 문제를 어떻게 발견하고 AI 진단 중 무엇을 받아들이거나 버렸는지와 근거 실행 결과. 문항 원문 틀은 `skills/explainback/SKILL.md` 3번.
- 교훈: 문항이 제출물(협업 기록·결정·검증 경로)의 **구체 사례**를 짚는다. 디버깅마다 `$debug` 5번 4칸(발견·AI 진단·받아들임/고침/버림·확인 결과)을 남기고, 155분 전후 탭3 에서 `$explainback` 으로 위 6틀을 한 번씩 써 본다.
